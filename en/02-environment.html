chapter 02

Setting Up the Environment

A VirtualBox VM playing the role of a dedicated server: minimal system, its own network on the LAN, hardened access from the very first boot.

note

The command blocks below indicate where to run each one: host is your physical machine, vm is the virtual machine. Mixing the two up was, by far, the most common source of error throughout this project — always worth double-checking before pasting.

1. Install VirtualBox

sudo apt update
sudo apt install -y virtualbox
vboxmanage --version

2. Download the guest OS image

Debian 12 (Bookworm), minimal install — light enough to run as a headless server, with stable repositories for everything that comes next.

mkdir -p ~/vm-isos && cd ~/vm-isos
wget https://cdimage.debian.org/debian-cd/current/amd64/iso-cd/debian-12.11.0-amd64-netinst.iso

3. Identify the host's network interface

Needed to configure Bridged mode in the next step — that's what makes the VM show up on your local network as its own device, with its own IP, instead of hiding behind NAT.

ip link show

Look for the interface that's actually connected (state UP,LOWER_UP) — usually something like enp2s0 or wlan0. Ignore virtual interfaces from any existing containers/VMs (docker0, virbr0, any veth*).

4. Create the VM

VBoxManage createvm --name "honeypot-lab" --ostype Debian_64 --register

VBoxManage modifyvm "honeypot-lab" \
  --memory 4096 --cpus 2 \
  --nic1 bridged --bridgeadapter1 YOUR_INTERFACE \
  --boot1 dvd --boot2 disk --boot3 none --boot4 none

# hardening: no shared clipboard/drag-and-drop with the host,
# no audio, no USB port, no remote display
VBoxManage modifyvm "honeypot-lab" \
  --clipboard-mode disabled --draganddrop disabled \
  --usb off --audio-driver none --vrde off

VBoxManage createhd --filename ~/VirtualBox\ VMs/honeypot-lab/honeypot-lab.vdi --size 20000
VBoxManage storagectl "honeypot-lab" --name "SATA Controller" --add sata --controller IntelAhci
VBoxManage storageattach "honeypot-lab" --storagectl "SATA Controller" \
  --port 0 --device 0 --type hdd --medium ~/VirtualBox\ VMs/honeypot-lab/honeypot-lab.vdi

VBoxManage storagectl "honeypot-lab" --name "IDE Controller" --add ide
VBoxManage storageattach "honeypot-lab" --storagectl "IDE Controller" \
  --port 0 --device 0 --type dvddrive --medium ~/vm-isos/debian-12.11.0-amd64-netinst.iso

5. Install Debian

VBoxManage startvm "honeypot-lab" --type gui

In the installer: text mode, guided partitioning (entire disk), and in package selection check only SSH server and standard system utilities — no graphical environment. After the first boot, always run it headless:

VBoxManage controlvm "honeypot-lab" poweroff
VBoxManage startvm "honeypot-lab" --type headless

6. Generate an SSH key (if you don't have one yet)

ls -al ~/.ssh
# if id_ed25519.pub doesn't exist:
ssh-keygen -t ed25519 -C "honeypot-lab"
warning

Don't copy the file without the .pub extension anywhere — that's the private key, it stays only on your machine.

7. Access hardening

Find the IP the VM got (router panel, or local console with ip a) and connect:

ssh-copy-id user@VM_IP

Then, inside the VM once connected:

sudo nano /etc/ssh/sshd_config
Port 2200
PasswordAuthentication no
PermitRootLogin no
PubkeyAuthentication yes
sudo systemctl restart ssh
don't close the session yet

Before ending the current connection, open a second terminal and confirm you can connect on the new port (ssh -p 2200 user@VM_IP). If something's wrong in the configuration and you've already closed the original session, you're locked out of remote access — you'd need to go back to the VM's graphical console.

Firewall, restricted to the local network:

sudo apt install -y ufw
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow from YOUR_SUBNET/24 to any port 2200 proto tcp
sudo ufw enable
sudo ufw status verbose
check both ipv4 and ipv6

A rule created without restricting the source (ufw allow 2200/tcp, without from) opens the port to any IPv4 and any IPv6 — if your network has public IPv6, this exposes the management port to the entire internet, with no port-forward configured for it at all. Always confirm the ufw status output shows your subnet, not Anywhere.

8. User with sudo

usermod -aG sudo your_user

Log out and back in (or newgrp sudo in the current session) and confirm with sudo whoami.

9. Install Docker

curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh
sudo usermod -aG docker $USER
# logout/login to apply the group

docker --version
docker compose version

10. Snapshot the clean state

A real advantage of running this in a VM: capture this point now, before bringing up any lab service.

VBoxManage snapshot "honeypot-lab" take "clean-hardened-os" \
  --description "Debian installed, SSH by key, UFW active"

If something breaks later on, you're back to this state in seconds:

VBoxManage snapshot "honeypot-lab" restore "clean-hardened-os"
